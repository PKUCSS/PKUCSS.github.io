## 总览
今天这两篇其实是同一个团队在同一套问题上的两步走：先把「列表效用 = 位置到达概率 × 条件价值」这个拆法做扎实，再拿它当奖励模型去引导生成式重排。最值得细读的是第一篇 [SurvEval](#note-1)，用离散时间 survival 的 hazard 连乘替代手写 position discount，让曝光衰减自己从数据里学出来，这是今天唯一让我觉得「有想法」的点；第二篇 [ReAlign](#note-2) 工程上更完整，但实验里从 Evaluator Only 到完整对齐只涨了零点几个千分点的 NDCG，说明收益基本被奖励模型吃掉了，对齐那套更像锦上添花。两篇共同的软肋也很一致：exit position 全靠播放时长阈值或最后一个点击反推，censoring 规则很粗，这个标签噪声直接决定 hazard 学得对不对，换个业务场景阈值就得重调，属于典型的「离线好看、上线要小心」。另外所谓多目标自适应其实只自适应了 loss 权重，最终聚合还是手调线性加权，别被标题唬住。今天优先看 [SurvEval](#note-1)，重点看它的 survival head 和衰减曲线怎么画的，[ReAlign](#note-2) 快速扫一眼生成器的候选 mask 和池构造就行。

### 1. SurvEval: Listwise Re-Ranking Evaluator via Survival-Based Exposure and Multi-Objective Value Modeling
- 论文链接：[AlphaXiv](https://alphaxiv.org/abs/2611.15434v1)
- 更新时间：2026-11-11 13:05 UTC
- 机构：Intuit Credit Karma
- 工业优先级：中
- 备注：5 Pages, 3 figures, ACM conference format

**排序评估器：别手写位置折扣了📉**

各位算法同学们，一个排在第 9 位的好 item，用户压根没滑到，离线评估器却当它“被看到”记了满额价值——这是现有 listwise evaluator 的默认假设。这篇来自 Intuit Credit Karma 的工作想把两件事拆开：用户能看到哪，以及看到了值多少。

📄 SurvEval: Listwise Re-Ranking Evaluator via Survival-Based Exposure and Multi-Objective Value Modeling

🔧 曝光端改成离散时间生存模型：第 t 位的退出概率建模成 hazard h(t)，reaching probability 就是前面所有位置 (1-h) 连乘，单调递减是结构自带的，不用再手写 position discount 那种凭感觉定的衰减函数；右删失（用户没退出、日志就断在这）也能进似然。

🧩 价值端不再把点击、时长、点赞揉成一个标量：K 个独立 value head，每个走加权逻辑回归（正样本按观测值加权），exp(logit) 还原 E[Y]；损失权重交给 uncertainty-based 多任务加权自己学，省掉手调多目标系数。

⚙️ 主干共享一个 transformer：item token 加位置 embedding，cross-attention 到 user token、self-attention 过列表，再分叉到 survival head 和 K 个 value head，最终 list 效用就是 Σ p(t)·v(t)，端到端联合训练。

📊 实验在 KuaiRand 和 Avito 两个数据集上做，不是单数据集自证。

📈 摘要结论是对 SOTA baseline 更优，对比对象覆盖现有 listwise evaluator 这一类。

✅ 图 3 的定性结果可以对着看：reaching probability 随深度单调下降，退出概率在中段出现单峰，和真实浏览直觉对得上。具体提升百分点在正文表格里，我没拿到数字就不硬编，你们看的时候直接对表。

😐 总结：做重排或做离线评估的同学可以跟，尤其是多目标量纲差得离谱、位置折扣靠凭感觉定的场景。要盯的指标是学出来的 list utility 和线上真实曝光深度、时长的相关性，不是离线排序指标本身。坑在日志：生存模型吃的就是真实退出位置，日志截断严重或位置偏差重，reaching probability 会学歪。和 PIER 这类两步式 evaluator 比，它的差异点是把“评估器”单独拎出来建模，而不是去改生成端。

### 2. ReAlign: Reward-Guided Preference Alignment for Generative Re-Ranking
- 论文链接：[AlphaXiv](https://alphaxiv.org/abs/2611.15445v1)
- 更新时间：2026-11-11 13:16 UTC
- 机构：Intuit Credit Karma
- 工业优先级：中
- 备注：9 pages, 3 figures, ACM conference format

**重排生成器终于吃到列表奖励了🔧**

各位算法同学们，两阶段“先生成再打分”的老流水线有个结构性问题：打分器再准，生成器也看不到列表级收益，梯度根本传不回去。ReAlign 做的事就是把这条断掉的线接上。

📄 ReAlign: Reward-Guided Preference Alignment for Generative Re-Ranking（Intuit Credit Karma）

🔧 奖励模型不把一个列表压成单个标量，而是拆成位置贡献加和：到达概率用离散时间生存模型刻画用户往下滑的过程，物品价值用多个目标头分别输出、再按不确定性加权，奖励因此既可解释也能校准。

🧩 生成器是 candidate-aware 的自回归模型，两段训练：先在曝光日志上监督预训练拿到相关性先验，再用奖励做后训练对齐，绕开了从随机初始化直接做偏好优化在冷启动下已知的不稳定。

⚙️ 后训练目标包含分布对齐和排序对齐两项，都算在池内标准化后的奖励上，所以对奖励的绝对尺度和有界偏差不敏感，这点比直接拿原始奖励套 DPO 类目标更稳。

📊 离线实验结论是 consistent 优于现有 SOTA 基线，作者摘要没给单点数字，具体幅度要去表格里看。

📈 评估口径是列表级期望效用（到达概率乘物品价值），不是单物品分数，和基线比较时先确认是不是同一口径。

✅ 训练顺序有讲究：奖励模型先在日志曝光和参与信号上学好，再对生成器做后训练，顺序反了前面的对齐就白做。

真正能抄走的是两个零件：奖励按位置分解、奖励池内标准化。要注意的坑也很明确，奖励模型本身拟合的是日志曝光策略，生存模型的位置偏差和日志的选择偏差会被生成器一起放大。做重排或生成式推荐的同学，落地前先盯列表级效用和曝光位置分布有没有漂移，对照组建议选 PIER、Seq2Slate 这类两阶段方法，同口径再谈提升。
